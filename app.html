How batch analyzer & ATS work

Batch analyzer (uses AI / Claude)

For each job in the batch, Claude reads the job's title, company, requirements, and interview process. It then drafts an answer to each of your Default application questions (configurable in Settings → Profile). Answers are tailored — they reference the specific company and tie to the JD when relevant. Custom Q&A you've added stays untouched. Output appears under Application Q&A on each job's detail page; you can copy, edit, or regenerate per job.

ATS check (no AI — pure keyword matching)

The ATS checker counts how many "ATS keywords" (from a curated list of ~100 frontend terms — React, TypeScript, accessibility, Storybook, etc.) appear in each JD vs. your selected resume version. The score is the percentage of JD-mentioned keywords that also appear in your resume, weighted by how often each keyword shows up in the JD. 100/100 = perfect coverage. Real-world ATS systems do something similar but with much broader vocabularies.

What "ATS scores vs resume v1" means

The check ran against the resume version you picked (e.g. v1, v2…). Different resume versions will give different scores. The intent: iterate on the resume between batches, save each version, and see which version scores best on similar JDs.

What "top gap" means

Top gap = the single keyword that appears most often in that JD but is missing from your resume. Closing it (i.e., adding the term to your resume in a defensible way) gives the biggest score lift for that job. The top keyword gaps across batch section lists keywords missing from your resume that appear across multiple JDs — closing those lifts several scores at once.

How to use this to improve your resume

  1. Run ATS check on a batch. Note jobs scoring < 60%.
  2. Look at the cross-batch gap list — start with terms missing from 2+ jobs.
  3. For each gap, ask: do I actually have this experience? If yes → rephrase an existing bullet to include the term. If no → leave it; don't invent.
  4. Click Improve resume on the batch — Claude suggests one specific bullet rewrite based on the gaps, saves it as a new resume version.
  5. Re-run ATS check using the new version. Compare scores. Iterate.

Cross-device sync (GitHub Gist)

Your app data (jobs, batches, criteria, resumes) syncs to a private GitHub Gist so it follows you across machines. API keys and gist credentials never sync — they stay only on each device. Auto-sync runs ~3 seconds after every change.

Create one at https://github.com/settings/tokens?type=beta — only the gist scope is required. Or use a fine-grained token with Gist read+write.
Setup flow:
1. On your first device: paste your token, click Create new private gist. Done.
2. On every other device: open the app, go to Settings, paste the same token AND the gist ID from step 1, click Pull from gist now.
3. After that, changes on any device auto-sync; other devices see them on next open or after Pull from gist now.
